## 0. 生效前提（首次部署必读）

1. 代码改动需**重启宿主进程并刷新页面**后生效；技能（skill）与考试卷（golden.yaml）即时生效。
2. 推荐配置环境变量（启动宿主前 export）：

```bash
export KB_RAG_STORAGE=/home/sjy-spark/Desktop/work/rag/lightrag/light-rag-docker/LightRAG/rag-storage-0.6B
```

不配置也可使用，仅影响两项自动能力（重复实体扫描、实体描述修改的自动考试），系统会自动降级为人工路径。

3. 重启后建议按顺序验证：
   - 对话中提问一个制度问题 → 应返回带引用答案；
   - 工作台 →「评测」→ 点「立即体检」→ 约 1 分钟出分数；
   - 工作台 →「概览」→ 应显示体检分数与近 7 天检索统计。

## 1. 日常使用：查资料

**操作**：在 dsh 对话中直接提问，例如"公司差旅住宿标准是什么？""网络电费稽核有什么要求？"。

**AI 的行为**（由 kb-usage 技能约束）：
- 先检索知识库，再基于检索结果作答，并在回答中标注来源文档；
- 检索无结果时明确说明"知识库暂无对应资料"，不会编造；
- 用户现实情况与库内资料冲突时，以用户现实为准并说明差异。

**自查入口**：工作台 →「运营」→ 检索流水，可看到每次查询的命中数、耗时与入口（AI/页面）。

## 2. 知识沉淀：把新知识放进库里

### 2.1 方式 A：AI 提案（推荐，日常会话内完成）

**场景**：会话中产生了可复用结论（排障方案、调研结论、决策依据），或发现库中某概念描述缺失。

**操作**：直接对 AI 说"把这条结论沉淀进知识库"，或让 AI 调 `kb_propose`。AI 会：
1. 打一份带证据链与自证题的提案；
2. 自动跑双条件考试（自证题 + 29 题回归）；
3. 补描述/建概念/补关系类：考试通过自动生效；
4. 删除/合并/整段入库类：弹出**审批卡**，展示理由与证据，人工点批准/拒绝。

**看结果**：工作台 →「提案」页，展开提案查看考试明细、生效状态与审计引用。

### 2.2 方式 B：工作台手动沉淀

**操作**：工作台 →「沉淀」→ 拖拽文件或粘贴文本 → 选主题 → 提交；处理进度在「文档」页查看（pending → processing → active）。

**注意事项**：
- 单文件 ≤ 100MB；PDF 因 MinerU 解析组件异常暂不建议（改用 docx/md/txt）；
- 同一来源重复沉淀会被拒绝，更新请走「文档」页的"替换"（先插新后删旧，失败不丢知识）。

### 2.3 方式 C：会话消息一键沉淀

每条 AI 回复下方的「💾 沉淀到知识库」按钮 → 填标题/正文/主题 → 提交；同一消息重复点击为幂等更新。

## 3. 体检：看知识库健不健康

| 入口 | 操作 | 产出 |
|---|---|---|
| 工作台「评测」→「立即体检」 | 点一次，约 1 分钟（只读，不改变知识） | 三项分数：找得到/认得全/读得全 + 逐题明细 |
| 对话中"做一次知识库体检" | AI 调 `kb_analyze` | 五类健康报告（源冲突/失败文档/重复实体/检索缺口），落盘并可后续回看 |
| 对话中"出一份知识库周报" | AI 调 `kb_report` | 近 7 天检索信号/提案飞轮/成绩趋势/健康概况 |

**看结果**：工作台 →「运营」页（体检报告、缺口清单、周报）；「评测」页（成绩与考试卷）；「概览」页（总览分数与待办）。

## 4. 治理：按体检结果动手修

### 4.1 处理检索缺口（优先做）

在「运营」页的缺口清单里，按分类处置：

| 分类标签 | 含义 | 处置动作 |
|---|---|---|
| 库里没有 | 知识确实不存在 | 联网调研后让 AI 用"新增资料"提案入库（需审批） |
| 偶尔波动 | 同参数重试即命中 | 暂不处置，观察趋势 |
| 内容不全 | 概念在、条文检不出 | 让 AI 提"补充描述"或"补条文"提案（自动考试，最有价值） |

**操作**：直接对 AI 说"处理运营页缺口清单里的第 N 条"，AI 会生成带证据与自证题的提案并走考试/审批。

### 4.2 处理重复实体候选

「运营」页体检报告里列出的"同名不同写法"（如 eNodeB / ENODEB）：
- 处置方式：**别名法合并**——建 `same_as` 关系 + 描述并入主实体（v1 禁用引擎级 merge，避免锚点风险）；
- 操作：对 AI 说"把 eNodeB 系列实体做别名合并"，AI 逐项提交提案（关系类自动考试生效）。

### 4.3 审批卡操作

- 审批卡出现在会话中（AI 发起破坏性提案时），卡上展示操作、理由与证据；
- 批准 → 立即生效并记账；拒绝 → 不应用任何变更，提案记为"已拒绝"；
- 事后追溯：工作台 →「审计」页（操作流水）、「提案」页（完整生命周期）。

## 5. 周期运营：让飞轮每周自己转

### 5.1 首次建立运营会话（一次性）

1. 新建一个专用会话（建议命名为"知识库运营"）；
2. **自动提醒（可选升级）**：当前预设未挂载定时提醒工具。如需"每周一上午 9 点自动提醒"，在 agent 预设
   （`~/.dsh/.agent-presets/liangshen/agent.cordis.yml`）追加一行后重启宿主：

   ```yaml
   - id: tool-schedule
     name: '@deepseek-ai/dsh-schedule'
   ```

   挂载后对 AI 说"每周一上午 9 点提醒我做知识库治理"（AI 调 `schedule_create` 建立周提醒）；
3. **当前默认做法（无需任何配置）**：每周由运营者手动开启——在运营会话里说一句"开始本周知识库治理"，
   或提前说"建立目标：完成本周知识库治理循环"（`create_goal`，会话内自动延续多轮）；
4. 治理启动后，AI 按 kb-gardener 技能执行：`kb_analyze 体检 → 逐项 kb_propose（考试/审批）→ kb_report 周报`，
   人只需在审批卡上点批准。

### 5.2 每周期望输出

- 「运营」页：新一份体检报告（四类数字变化趋势）；
- 「评测」页：新的成绩记录（分数应持平或上升）；
- 「提案」页：本周提案及批准率；
- 周报落盘 `storages/dsh-knowledge/reports/weekly-<日期>.md`。

## 6. 部署与维护

### 6.1 环境变量

| 变量 | 用途 | 默认 |
|---|---|---|
| `KB_RAG_STORAGE` | 引擎活库宿主路径（重复实体扫描 + 实体描述前值捕获） | 未配置（能力自动降级） |
| `LIGHTRAG_BASE_URL` | 引擎地址 | `http://127.0.0.1:9623` |
| `KB_DATA_DIR` | 插件数据目录 | `${DSH_HOME}/storages/dsh-knowledge` |

### 6.2 发布流程

改代码 → `node --check` 校验 → 跑自测（`dev/flywheel-unit.mjs`、`dev/analyze-unit.mjs`、`dev/selfcheck-curator.mjs`）→ 重启宿主 → 刷新页面 → 按 §0.3 验证。

### 6.3 数据备份建议

- 引擎活库目录 `rag-storage-0.6B/`（约 4GB，含图/向量/索引）；
- 插件数据目录 `storages/dsh-knowledge/`（注册表与全部账本，体积小，建议随日常备份）。

## 7. 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 图谱编辑提示"管道忙碌" | 引擎正在处理入库/删除任务 | 稍等重试；删除类任务可能持续数分钟 |
| 提案被拒，原因是"冗余" | 自证题在现网已能答上，说明知识已存在 | 无需处理，属于正确拦截 |
| 提案被拒，考试明细显示"变差" | 回归考试分数下降（含引擎自然波动） | 属安全方向拦截；如需再次尝试可隔几分钟重提 |
| 补描述类提案总是走审批 | 未配置 `KB_RAG_STORAGE`，前值捕获降级 | 配置环境变量后重启宿主 |
| PDF 上传失败或处理异常 | MinerU 解析组件异常 | 改用 docx/md/txt 等格式 |
| 工作台提示"引擎不可达" | 引擎容器未运行或端口不通 | 检查容器 `lightrag-docker-0.6B` 与端口 9623 |
| 想查某次改动是谁做的 | — | 工作台 →「审计」页（动作/操作者筛选）；提案类再看「提案」页 |
