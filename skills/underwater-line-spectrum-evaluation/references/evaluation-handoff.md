# 评价交接与波束协作

状态：交接语义规范 0.1；EvaluationRequest、TruthCoverage、EvaluationResult 字段契约 0.1.0，TruthLabels 契约 1.0.0，评价运行时 1.0.0。已实现单文档检查、跨文档预检和数值评价，见 [字段格式与检查](schema-validation.md) 与 [评价执行器 V1](runtime-v1.md)。尚无自动索引服务。已有 DetectionResult 的 schema_version=0.1.0 不变，不向其加入未定义字段，也不改旧接收脚本。

## 1. 职责与证据归属

| 模块 | 负责 | 不因交接而获得的权限 |
|---|---|---|
| 波束形成 | 指定波束时域、已有空间/谱产物及其元数据 | 自动选目标、生成未请求的全部波束时域 |
| 线谱检测 | 所选规则、谱估计、门限/候选及判据、处理覆盖 | 替评价认定候选真假或改写真值 |
| 线谱评价 | 指标定义、证据适用性、已确认的匹配/统计、可比性和限制 | 重新检测、调门限、标定系数、自动回写上游 |

来源追溯、按需联合查看与比较、经确认进一步计算这三个层次继续保留。分 Skill 不意味着切断数据关系，也不意味着建立自动反馈循环。

## 2. 检测向评价提供的最小信息

按所选指标读取必要部分，不默认复制原录音或完整矩阵。可靠信息通过核对过的引用继承；交接缺失项不能让评价端猜测。

| 信息组 | 需明确的语义 |
|---|---|
| 结果身份 | 结果定位/内容摘要、run_id、task_id、结果契约版本和状态 |
| 输入与波束身份 | 来源包摘要 + signal_id；有波束时保留上游 result 摘要 + 波束算法 + beam_id；单阵元不伪造波束 |
| 实际处理方案 | 检测器身份/版本/实现、实际参数与确认引用、谱参数、CA/OS 选择、门限路线及配置/标定来源 |
| 范围与覆盖 | 请求范围、实际处理时间/频带、有效掩码/排除原因；逐窗状态或可核验等价信息，必须覆盖成功零候选窗口 |
| 候选及完整性 | candidate_id、原频率定义、分析支持时间、任务归属、实际事件范围或未估计声明；候选列表是否完整、截断/筛选/导出范围 |
| 最小判据 | 可解释的原判据或证据引用；有峰值/背景/门限时保留定义、单位与尺度，不虚构不具备的字段 |
| 证据可用性 | 谱/图/判决等在内存、临时文件、持久包、外部引用还是已不可用；持久文件定位与摘要 |
| 限制 | 已接受假设、标定状态、模型与阵列限制、未知项和数值诊断 |

候选身份以 run_id + task_id + candidate_id 限定，不用频率/方向值单独识别对象。保存列索引和原扫描列索引分开；方向需有坐标、零向和正向定义。评价不能因文件名或角度相同就混合来源。

DetectionResult 0.1.0 已声明部分来源、coverage、candidates、decision、artifacts。V1 执行器仅在完整候选 product 和 ledger 通过摘要、身份及计数核对后计算；单元指标还要求 tested_bins 与越门限组证据。历史包缺少这些证据时报告指标不可算，不从最终候选数倒推单元概率。

后续可按指标设计补充独立证据产物或升级契约；需要与生产端逐字段映射、校验及测试。不得偷偷把新语义塞进已有严格 Schema，或伪造每帧记录、单元掩码与零检出窗口。

## 3. 真值与背景单独交接

真值不是 DetectionResult 自动生成的附带结论。评价另行接收其引用/摘要、来源与获取方法、标签对象与粒度、时频覆盖、完整/局部/未知区、争议标签、单位/时间映射、独立性与可信条件。

人工标注可以是真值来源，但需记录覆盖和限制；根据检测图回填的标签不是天然独立验证。没有真值就明确“无真值”，不创建空表假装完整负样本。只有理论预期时标为预期参照，不升级为真实存在证明。

可信背景的 H0 定义必须与被评价任务对应，并有依据支持；不能自动把最安静片段、离开主瓣方向或未标注频段设为纯背景。

## 4. 评价请求与结果的语义

EvaluationRequest 0.1.0 的内容包括：

- 所评价结果/任务/信号及时间频带范围；问题与所选指标。
- 真值/背景证据和覆盖状态；明确没有与尚未确认要区分。
- 所需匹配、重复处理、统计层级、分组和分母规则。
- 比较对象、可比性条件、接受的限制和未决项。
- 计算、展示、保存选择；必要的确认与证据引用。

EvaluationResult 0.1.0 的内容包括：

- 独立 evaluation_id、请求和配置引用、输入结果与证据身份。
- 每个所选指标的定义/版本、数值或空值、单位、分子/分母、实际评价范围、排除项与方法。
- 逐指标状态，例如已计算、未请求、待确认、证据不足、不适用、未实现或失败；不能只用一个 overall completed 掩盖不可算项。
- 真值匹配表仅在确实计算且按请求保留时提供；关联原 candidate_id，不重写候选。
- 观察、解释、假设与建议分开；名义/模型/标定/独立验证结论分开。
- 产物与来源引用、可用性、保存状态、局限及另行建议的追加请求。

这些对象已有严格序列化格式。EvaluationRequest 是 V1 执行入口，但只有本地结构检查通过仍不可执行；还必须通过跨文档预检。字段的准确位置、允许状态及限制见 [字段格式与检查](schema-validation.md)，不能按语义列表任意增加字段。未请求指标无需填满一张大表。评价过程完成不代表全部指标可算，也不代表工程验收通过。

## 5. 联合查看与受控追加

由候选定位来源波束、已有谱图及相应时间频率位置时，先核对原时间映射、频率网格、单位/参考和有效覆盖。只有出处一致并不保证数值可比；未知轴、最近频点取法、插值或对齐规则先解决再计算。

频率—角度平均图只描述其平均范围；宽带 BTR 不是单条线谱的时间—角度证据。缺少细分空间结果时提出新计算需求，不能从宽带图“读出”不存在的单频证据。

CBF/MVDR 或 CA/OS 的共同候选可以呈现为同源一致现象，不自动合并为同一目标、不以算法投票制造真值。需要关联容差时先明确，不能默默用最近邻。

追加请求列出：父结果/候选、要回答的问题、责任模块、所选范围、缺失输入/参数、预计产物、确认与执行状态。评价模块可以提出请求，不能据此自动启动。新结果另分身份，保留旧结果，评价与关联记录在外部引用旧包而不是向旧包回写。

## 6. 按需保存与恢复

若用户只看结论，使用现有可用证据，不为“以后也许要用”保存大矩阵。若保存指标或图，随附最小来源、定义、配置、范围、证据条件与限制；外部引用不冒充已经打包。

评价某指标所需的细粒度证据未保存或已丢失时，报告不可复查/不可算，并说明可选补算。不能悄悄重建原检测或承诺永久索引。需保留分母和判决摘要时，在下一次检测的输出计划中提前确认，而不是要求所有历史结果具备未设计过的字段。
