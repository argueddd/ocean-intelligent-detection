# 波束形成评价

评价已完成并保存的波束形成结果。中文请求默认用中文报告。保留上游算法、beam ID、方向定义、处理频带、时间覆盖和文件摘要；不修改上游结果。

## 当前能力

版本 1.0.0：

- 数值评价：`P(theta)`、DOA 序列、`P(f,theta)`、BTR `P(t,theta)`、波束时域信号、输出频谱/PSD、`P(t,f)`。
- 对比评价：论文相对排名、证据完整度、工程阈值与 `critical=true` 一票否决。
- 结果展示：对比图、Pareto 图、场景曲线和雷达图。图只辅助解释，不覆盖数值与证据结论。
- 可审计运行：`EvaluationRequest` / `EvaluationResult` 1.0.0，输入 SHA-256 核对、只读预检、新目录原子发布、产物清单和摘要。

已用 SWellEx-96 S59 VLA 的已保存 CBF/MVDR 产物完成6任务只读集成验证；详见 [实测流程验证](references/real-data-validation.md)。该证据不含方位真值，不代表定位或工程验收通过。

## 职责边界

| 问题 | 负责模块 |
|---|---|
| 如何从阵元数据得到波束、扫描方向和输出谱 | 波束形成 Skill |
| 已有波束结果表现如何，证据支持什么结论 | **本 Skill** |
| 频谱某频率单元是否是线谱候选 | 线谱检测 Skill |
| 线谱检测结果的检出、误报和频率误差是否可信 | 线谱评价 Skill |
| 不同时间的候选是否是同一条线/同一个运动目标 | 轨迹跟踪模块 |
| 多条线谱、方位和其他特征是否来自同一声源 | 声源关联/融合模块 |
| 声源是什么目标 | 目标识别模块 |
| 下一轮试哪些参数并重跑 | 迭代调优/流程编排模块；本 Skill 只给出证据化建议 |

无真值 BTR 的“最强连续脊线”只是显示稳定性描述，不是目标跟踪。已经显式给定目标频带的时频连续性也不是自动线谱检测。

## 证据门禁

先确定能够使用的最高证据级别：

1. 只有图像：只做定性/有限半定量观察；不从低分辨率图中制造精确指标。
2. 无真值数值结果：可报峰位置、HPBW、旁瓣、假峰、脊线连续性和背景对比；不报定位精度、目标真实性或工程通过。
3. 有可比基线/输入：可报相对改善量，但要先核对数据、时频范围、处理和尺度可比。
4. 有覆盖明确的真值：可报 DOA 误差、漏检、虚警和真值轨迹连续性；结论只适用于真值覆盖。
5. 有明确阈值与独立验证数据：才能做工程验收；缺值不填 0，缺失的阈值指标不能判“通过”。

完整规则见 [证据、可比性与结论边界](references/evidence-and-boundaries.md)。

## 自主评价策略

用户要求“评价/看看效果/比较结果”即授权执行所有现有证据支持且与问题相关的指标，不再逐项询问指标、图表、输出目录或是否开始。先自动判断最高证据等级：无真值时做描述性评价，有可比基线时增加相对比较，有覆盖明确的真值时增加误差指标；缺少更高等级证据只降低结论，不阻断低等级评价。

- 结果类型、数组轴、尺度和覆盖能由结果包及来源清单唯一确定时直接使用；冲突无法裁决时才询问。
- 用户未指定指标时选择该结果类型的全部核心可计算指标，必要诊断图默认生成；不会计算的项省略或标记证据不足，不要求用户逐项决定。
- 多个算法结果满足同源、同范围和同尺度时自动比较；不满足可比性时分别评价，不为“能排名”而改数据。
- 没有验收阈值时把 acceptance 设为 `not_requested`，继续完成评价；不会询问用户临时编一个阈值。
- review/preflight 通过且原请求要求评价时直接 execute。只有多个 primary 结果同样合理、核心轴/尺度仍冲突或真值语义无法确定时，才把全部阻断项与推荐选择合并成一次“需要你确认”清单。

## 工作流程

1. 分类结果类型，核对数组轴、单位、线性功率/幅度/dB 尺度、时频范围及上游完成状态；能由契约唯一确定时直接采用。
2. 记录场景：阵型、近/远场、宽/窄带、算法、快拍、干扰、多途/混响、校准和平台运动。
3. 声明真值、基线、可比性、独立性和验收阈值状态；不把预期方位或最强峰当真值。
4. 从 [数据到指标](references/data-to-metrics.md) 中只选证据支持的指标，按 [指标定义](references/metrics.md) 解释。
5. 数值运行使用 1.0.0 请求契约和新输出目录，先 `--preflight-only`；通过后按原请求直接执行。
6. 分开报告“测得事实”、“有依据解释”、“待验证原因”和“下轮建议”。参考 [报告模板](references/report-template.md)。

## 执行入口

批量可审计评价见 [运行时 V1](references/runtime-v1.md)和 [上下游交接](references/evaluation-handoff.md)：

```bash
python3 -B scripts/validate_contract.py request.json --expect EvaluationRequest
python3 -B scripts/evaluation_runtime.py request.json --preflight-only
python3 -B scripts/evaluation_runtime.py request.json --output-dir /absolute/new/output
```

单项计算可直接使用 `scripts/beamforming_metrics.py`：

- `spectrum`、`doa`、`freq-bearing`、`btr`
- `signal`、`spectrum-output`、`time-frequency`
- `compare`、`plot-compare`、`plot-pareto`、`plot-scenario-curves`、`plot-radar`

命令参数及轴约定以 `--help` 和 [数据到指标](references/data-to-metrics.md) 为准。当首个角度为负数时，行命令使用 `--angles=-90,...,90`。

## 强制规则

- 不以峰高单独判断波束质量；同时检查偏差、主瓣宽度、旁瓣/假峰、稳定性和目标保真。
- 不在阵列几何、输入、预处理、频带、快拍和场景不可比时排名算法。
- 无真值不报 DOA RMSE；无目标/噪声/干扰分离不报严格 SNR/SINR；无基线不报改善量。
- 只有图像时不虚构 HPBW、PSL、RMSE 或 SNR 的精确数字。
- 自适应波束结果要核对协方差估计、快拍、对角加载、导向失配和 WNG/稳健性证据。
- 水声实测结论要显式考虑多途、混响、色噪声、声速失配、阵列标定和平台运动。
- 建议阈值只能标为建议；不得冒充用户/项目的已批准验收标准。
- 调优建议必须指向具体证据、预期影响和验证指标；本 Skill 不自动改参数或重跑上游。

## 默认输出

1. 总体结论与证据等级
2. 场景、数据覆盖和可比性
3. 指标表及定义
4. 可见/可计算现象
5. 限制与证据不足项
6. 论文证据视角（如适用）
7. 工程验收视角（仅在有阈值时）
8. 下一轮实验/调优建议，不自动执行
