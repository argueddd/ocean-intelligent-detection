# 跟踪方法 1.0.0

## 处理顺序

检测行按连续零基 `row` 顺序处理。每行先计算活动轨迹的预测频率，再建立轨迹—候选可行边；随后做最大匹配数、最小总代价的一对一全局分配。未匹配候选各自建立一条新轨迹，未匹配活动轨迹按所选 gap 策略累计漏行。

该顺序不会把同一候选分给多条轨迹，也不会让同一轨迹在一行吸收多个候选。

## 预测

- `last_frequency`：预测值等于轨迹最后一个真实观测频率。
- `constant_velocity`：至少有两个不同时间的真实观测时，用最后两点斜率外推；否则退回上一频率。

预测只用于候选关联，不新增轨迹点。没有候选的时间行不做插值输出。

## 门控

每条可行边必须同时满足所有已启用条件：

1. `abs(candidate_frequency - predicted_frequency) <= frequency_gate_hz`；
2. 变化率门限非 null 时，`abs(candidate_frequency - last_frequency) / dt` 不超过该门限；
3. 功率门限非 null 时，候选与轨迹最后一点的 `abs(10*log10(P2/P1))` 不超过该门限。

边界值视为通过。`dt` 必须为正；检测行时间不严格递增时阻断。门限不是测量不确定度、置信区间或目标物理机动上限，除非外部证据明确定义如此。

## 代价与冲突

可行边代价为：

```text
frequency_cost_weight * frequency_residual / frequency_gate_hz
+ power_cost_weight * power_change_db / power_change_gate_db
```

功率项仅在功率门限启用时允许非零。分配先最大化本行匹配数量，再最小化总代价。完全相同代价按已有 `track_id` 与 `candidate_id` 的稳定顺序决定，以保证重复运行得到相同结果；这个规则不表示物理优先级。

轨迹交叉处仅凭当前配置和有限历史可能发生身份交换。此版本不使用声源身份、谐波关系、未来全局平滑或人工标签消除歧义，必须在限制中保留。

## 生命周期

- 未匹配候选立即建立 tentative 轨迹；不会因为点少而丢弃候选。
- 检测点数达到 `min_confirmed_detections` 后标记 confirmed；这是确定性状态，不是概率。
- 未匹配活动轨迹按 `gap_count_basis` 计数。计数大于 `max_missed_rows` 时终止。
- `tested_rows_only` 不对上游 `skipped` 行计数；`all_rows` 会计数。两种策略都保留原行状态。
- 输入结束时仍活动的轨迹以 `end_of_input` 终止；此前超限的轨迹以 `gap_exceeded` 终止。
- 已终止轨迹不会复活。更晚出现的候选只能建立新轨迹；本版本不做离线轨迹拼接。

## 描述量

每条轨迹输出起止时间、点数、频率最小/最大/均值和对全部真实点做普通最小二乘得到的频率斜率。它们是对已关联点的描述，不是目标速度、类别或跟踪精度。
