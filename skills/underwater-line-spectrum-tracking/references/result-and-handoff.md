# 结果解释与下游交接

## 身份层级

必须区分：

1. `run_id + task_id + candidate_id`：上游检测候选；
2. `tracking_run_id + track_id`：本次候选—轨迹关联；
3. 轨迹—谐波族、声源或现实目标关系：本模块未生成；
4. 目标身份：本模块未生成。

频率接近、同一波束、轨迹连续或 confirmed 均不能越级成为同源或同目标证据。

## 结果字段

- `tracks`：所有轨迹，包括 tentative 短轨；不静默丢弃单点候选。
- `candidate_track_associations`：每个输入候选恰好一条映射；新建轨迹的首点标记 `new_track`。
- `row_ledger`：每个输入检测行的状态、候选数、匹配数、新轨数、未匹配活动轨迹数和终止轨迹。
- `coverage`：完整行数、tested/skipped/零候选行数、候选数及时间范围。
- `semantic_boundary`：明确未执行的谐波、声源、目标、身份和评价工作。
- `limitations`：当前算法、输入和证据不能支持的结论。

## 报告要求

报告至少包含：

- 来源检测 `run_id`、`task_id`、交接摘要；
- 实际预测模式、全部门限、gap 策略和确认点数；
- 总轨迹、confirmed、tentative、候选映射及检测行覆盖；
- 交叉、漏检、跳过行、无功率门控等相关限制；
- 结果目录和 package manifest；
- “已生成轨迹，但未评价真实性/准确率，未进行目标归属或身份识别”。

## 后续模块

- 跟踪性能、轨迹连续性、身份交换、起止延迟和真值误差交给独立的“线谱轨迹跟踪评价”。
- 谐波/边带/调制结构和多特征组合交给“谱结构与多特征融合”。
- 多条轨迹属于哪个声源或目标交给“声源/目标归属”。
- 现实目标类别或身份交给“目标身份识别”。

下游只读消费本结果并引用摘要；不得回写本结果或把评价/识别字段补进既有轨迹包。
