# 六项工作与验收清单

本清单用于核对这个 Skill 的实际能力，不把“代码能运行”或“没有 NaN”当作数据全面合格，也不据此进入新的预处理模块。机器可读子项与以下 21 项一致，见 scripts/acoustic_inspection/coverage.py 的 CATALOG。

普通数据任务仅按当前请求核对能力、状态和覆盖，不运行下方开发者验收。已有有效 JSON/CSV 足以回答时直接复用；不会因读取本清单而扩大范围、另写读取器或重跑分析。

## 先分清三件事

1. 基础流程是否执行完：result.status 和 CLI 退出码。
2. 每个子项有没有实现、这次是否完成：checks；六项汇总见 stages.*.assessment_status。
3. 究竟检查了哪里：checks.*.coverage，同时比较请求范围与整个源文件。

任何一步缺信息都保留已有证据。允许确认不了，但必须准确报告；不允许为了得到“全部完成”而补造采样率、单位、坐标或故障结论。

## 六项、21 个子项

“已实现”表示有可运行能力，不表示本次一定完成，更不表示数据合格。

## 运行状态的判定

- completed / 已完成：这一子项有执行证据，覆盖它的请求范围；发现异常仍可表示检查执行完毕，不能解读为合格。
- partial / 部分完成：只完成部分请求样本、通道、完整窗口或通道对；同时列出成功范围。
- blocked / 受阻：已有实现，但缺元数据、前置步骤未完成、配置有问题或样本不满足计算条件；报告最小所需信息或调整。
- not_implemented / 尚未实现：无对应检查能力，不能说补充一个参数即可运行。
- not_run / 本次未运行：当前模式未请求，或没有执行证据；不冒充功能缺失。
- not_applicable / 不适用：例如仅一个通道时无通道对。
- failed / 执行失败：运行错误或源一致性核对失败，记录原因。
- invalidated / 结果失效：源改变导致已产生的成功证据不能再用于结论。

阶段汇总遇到失败/失效显示失败；已完成与受阻、未实现、未运行混合显示部分完成。统计清单也展示未实现能力，但它们不改变原 CLI 对“已支持基础流程是否成功”的退出码约定。历史 status 的调用方不要将其作为完整验收标记。

## 开发者验收（读取器改动或明确验收任务时）

修改脚本后运行完整 unittest 集合；新增或修订 Skill 说明时运行 skill-creator 的结构校验。两者都不能取代读取器改动所需的真实片段验证，但它们不是每次数据分析的前置步骤。

- tests/test_inspection.py：字段与轴歧义、采样率冲突、单位缺失、原始值不变、分块指标、异常区间、已知频率与功率、短数据与预算。
- tests/test_sio.py：大小端、数值类型、记录边界、填充排除、文件头/长度异常、缺 fs 时禁止频谱。
- tests/test_coverage.py：四类核心状态不混淆、明确子范围不冒充全文件、预算和未用尾部标部分、单通道/恒值/非有限数据、缺失配对、源变化使证据失效、CSV/JSON 一致、报告展示数值配对证据。

SWellEx-96 S59 VLA 是已有的开发验收案例：全量 65 分钟 21 通道样本检查，前 60 秒第 1/11/21 路基础分析。只有相关读取器/流程改动或明确要求重做该验收时才执行这个固定案例。保留配置与来源；独立对照首尾、跨记录和边界的小片段；只重跑变更影响的步骤并查看相应报告。全量检查报告里的谱分析应为“本次未运行”，局部分析报告不能称为全时段全通道分析。未确认单位和三维坐标应为受阻；四项未实现能力必须一直显式保留。

同一个 S59 文件通过验证，不代表其他实验、阵列或所有格式都已经真实验证。

## 如何推进未完成内容

先区分两种工作：已有能力的报告/覆盖缺口可直接修正并测试；尚未实现的参考驱动检查需先确定输入数据和判据，再决定开发。未得到采集时间参考、ADC 编码或标定实验时，继续报告限制，不写猜测算法来凑齐“六项完成”。
