# 水声数据读取与检查分析

把用户指定的原始水声数据转成可追溯的数据描述、检查证据和基础分析结果。默认中文解释。六项工作：文件探查、数据读取、标准数据模型、完整性检查、通道与阵列质量检查、初步信号分析。

## 先确定本轮任务

- 纯解释术语或已有报告字段无需调用本 Skill。若已加载，仍直接回答当前字段的定义和必要影响，遵守用户或运行环境的字数限制；不加入示例数值、成因、设备背景或新任务建议。必要时只读已有结果的相关字段，不读取原始波形、运行分析、演示字节或修改报告；未记录的事实保留为未知。
- 读取、体检或分析数据：使用本 Skill 已提供的脚本，按请求范围执行。用户只要“数据检查/体检”时用 mode=check，不自行追加 analyze 或先全量检查再做局部谱。普通“简要分析”只交付该范围的基础统计、波形、PSD 和时频结果，不自动追加峰检测、时间稳定性、带能量脚本或视觉验收。只有明确要求额外指标时才读取 NPZ 计算。用户已提供的有效结果足以回答时复用；不为寻找旁证扫描历史 probe、配置或报告。
- 开发或验收 Skill：仅在明确要求修改读取器/分析代码或验收能力时，执行文末验证流程。日常分析不以前置独立读取器、全量回归或 S59 固定验证流程为条件。

## 必要规则

按需要查参考：配置细节见 [数据契约](references/data-contract.md)；事实缺失/歧义/冲突见 [不确定信息规则](references/uncertainty-rules.md)；指标解释见 [质量规则](references/quality-checks.md)；分析设置或明确读图需求见 [分析规则](references/analysis-guide.md)。已具备所需事实的常规任务直接走下方快速执行，不先加载全部参考或读取脚本实现。

字段语义、轴语义、采样率、单位、通道映射、几何与标定属于数据事实。优先使用格式规范、文件头、唯一字段、显式维度标签和已有可信配置；这些证据能唯一确定时直接采用并记录来源，不再询问。仍有多个实质可行解释时记录歧义，只暂停依赖该事实的步骤。窗长、重叠、块大小、通道展示数量、分析预算和输出图属于可逆设置，由本 Skill 根据任务与数据规模直接选择并保存。

## 自主决策与一次性提问

- 用户要求“体检/检查”即授权执行 `mode=check`；要求“分析/看一下特点”即授权在已知采样率时执行基础 `mode=analyze`。无需另问是否开始、是否画图或是否采用脚本默认窗。
- 只有一个受支持的数据文件或一个结构上唯一的波形数组时直接选择；若有多个同等合理对象，先完成目录探查，再一次列出候选并推荐最可能项。
- 采样率缺失时仍完成样本域统计、非有限值、恒值段和通道相对质量。仅当用户的核心问题依赖秒或 Hz 且无可信来源时才询问采样率；单位、几何或标定缺失不阻断原始数值和相对分析。
- 能由 `fs` 和目标频率分辨率推导的窗长直接计算；用户未给分辨率时采用脚本基线设置。数据超过预算时选择覆盖明确的代表性通道/区间，不声称代表未分析部分。
- 确需输入时，先完成所有不依赖答案的检查，再把当前全部阻断项放进一个“需要你确认”清单；每项给推荐选择、备选和影响，允许用户回复“按推荐执行”。

需要解释子项状态时，读 [六项工作与验收清单](references/acceptance-checklist.md) 的能力与状态部分。区分基础流程执行状态、每个子项的能力/执行状态、以及实际覆盖范围；不得把顶层 completed 解读成六项全部完成。该参考中的开发者验收不适用于普通数据任务。

## 日常快速执行

采用当前请求或可信来源已确定的路径、字段/轴、采样率和范围，并使用本 Skill 自主设置；用户明确给定的事实无需再搜索外部文档、README 或历史配置证明。probe 只检查它们与当前文件结构是否相容，不再次证明已具来源的语义。未要求新指标时，不读实现、不猜 NPZ 键名、不组织额外核验。

1. 无文件时只请求路径；只有目录时用 execute 一次列出数据候选、结构和已有配置文件名。只有一个受支持主数据文件或已有配置唯一绑定某文件时直接选择；多个同等合理记录才合并询问。确切路径优先；缺失的 /卷名/路径 可唯一映射到 macOS /Volumes，零个或多个匹配停止并说明，不搜全盘。
2. 有明确文件时，直接用 execute 加 --config-json 传最小配置，或 --config 使用唯一匹配的已有配置。入口一次完成 probe、原配置校验、读取/检查/分析，并把摘要内容返回 stdout；无需另跑 probe、手写配置文件或 cat 摘要。配置只写证据支持的数据事实和本次自主设置，单位/映射/几何未知时省略。字段或轴能由格式、标签或唯一结构候选确定时直接采用；仍有多个实质解释时才受阻。采样率缺失/冲突仍先做样本检查，只暂停秒/Hz 分析。
3. 时间区间按已确认 fs 换算样本；请求网格间距 Δf 可推导 nperseg=fs/Δf，必须为合法整数且不超过所选样本数，否则说明设置限制。显式范围与分析预算分开记录，不能默认截短范围却声称完整覆盖。每次使用新输出目录，不覆盖源文件或既有结果；实际冲突必须有用户选择及理由才能解决。
4. 用 stdout 的 summary、numeric_summary 和 figure_paths 直接组织对话答复。numeric_summary 已含零值总数、均值/标准差/RMS/极值范围及最长恒值段；figure_paths 是全部实际生成图的绝对路径，不为求这些指标或图名再 cat/ls 或写汇总脚本。仅在信息不足或执行受阻时读相关 JSON/CSV 字段。足以回答就结束；明确要求报告时按下方规则整理文件。不复算已有指标，默认不追加 NPZ 派生分析或视觉验收。结果复用条件见 [数据契约](references/data-contract.md)。

若出现读取器错误或证据矛盾，记录错误、受影响范围及已有有效结果，暂停受影响步骤。普通数据任务不自动修改共享 Skill 脚本，也不轮流更换字节序、字段或轴直到能跑；只有进入明确的修复开发任务才修改并验证。

## 交付规则

普通分析把内容直接呈现在对话中：先给有数值依据的结论，关键指标用简短表格，按需要呈现实际生成的图，再用一句话说明影响结论的覆盖或元数据限制。只有受阻或用户要求时才给必要下一步；不以报告链接代替分析内容，不主动整理正式用户报告。

脚本自动生成的 summary.md 是内部内容来源，report.md 是保留兼容的技术明细，JSON/CSV 保留完整证据；这些文件的自动生成不代表用户要求了报告。不要照抄摘要中的产物清单、后台说明或全部限制。源文件只读/未修改、产物目录、能力完成清单及与本轮无关的重复未运行项不写进对话或用户报告。执行失败、事实冲突、源变化导致证据失效等实质问题仍须明确告知，并暂停受影响步骤。

用户明确要求“总结成报告”“整理报告”或同义请求时，从已有 summary.md/result.json 及必要指标汇总一个新的用户报告 Markdown 文件，不覆盖既有证据；不重新读取原始数据、执行分析或调用视觉工具，不为整理报告新增分析。报告包含结论、关键指标、必要图表和实际覆盖限制，不直接把内部技术 report.md 作为用户报告。

报告和图表使用标准 Markdown 链接或图片语法，不用反引号罗列路径、裸路径或产物目录。对话中的文件链接优先用绝对路径，也可用界面支持的工作区相对路径；图片用 `![具体图名](图像路径)`，文件用 `[报告名称](报告路径)`，带空格的路径用尖括号包裹。用户报告内部的图表使用相对报告文件的路径（如 `![PSD](psd.png)`）以便预览。只链接实际存在且与结论相关的产物。

dtype、字节序、头部偏移和存储填充保留为机器证据或技术附录；除非它们阻断读取、影响结论或用户正在询问，不占正文。区分存储填充与谱估计未组成完整窗口的末尾样本，不猜测填充区的实际内容。

使用简洁专业的陈述。不要写“好问题”“我来”“我用真实字节”等开场、过程口水或自我调试经过。引用具体图名（如 psd.png、spectrogram_ch0.png）、通道、范围和数值，不用无名称的“图一/图二”。推测明确标注，发现异常不自动认定数据故障，脚本 completed 不等于数据合格。

需要 SIO 布局或未确认元数据的来源说明时，读 [SIO 读取与元数据来源](references/sio-swellex96.md)。SIO 的字段、轴与字节序由已验证格式确定，但采样率、通道身份、单位和几何不能从文件名推断；用户已给定的值直接记录来源为当前指令，不另查发布者页面。

## 执行入口

下述路径以本 Skill 为基准；执行时使用绝对路径。Python 3.10+，依赖见 scripts/requirements.txt。先检查现有环境，缺依赖时报告，不擅自修改全局环境。

```bash
python3 <skill-dir>/scripts/inspect_data.py execute <data-file> --config-json '{"mode":"check","sample_axis":0}'
python3 <skill-dir>/scripts/inspect_data.py execute <data-dir> --file <relative-data-file> --config <explicit-config.json>
python3 <skill-dir>/scripts/inspect_data.py execute <data-dir>
```

execute 优先：配置必须明确给定；--config 与 --config-json 二选一，未知参数、重复 JSON 键及 NaN/Inf 会拒绝。未给 --out 时在当前工作区 .run 下新建唯一目录；stdout 含路径解析证据、状态和完整摘要，可直接回答。目录输入没有 --file 只探查结构候选，不做数值体检；--file 必须相对该目录且不能通过 .. 或符号链接逃出边界。目录配置仅列文件名，不推导文件选择、采样率或通道身份。

旧入口保留用于单独结构探查或已有调用方，输出仍为原 JSON 状态：

```bash
python3 <skill-dir>/scripts/inspect_data.py probe <data-file> --out <new-probe-dir>
python3 <skill-dir>/scripts/inspect_data.py run <data-file> --config <config.json> --out <new-result-dir>
```

probe 只确认格式结构，不确认未知字段语义。run 默认 mode=check；完整基础分析显式用 mode=analyze。退出码 0 表示请求阶段完成，2 表示信息不足或部分结果，1 表示执行失败；非零退出时阅读 JSON 原因，成功时从 summary.md 组织对话答复。

### 最小配置示例

以下仅示范合法配置，不是默认数据事实：probe/用户已确认字段 data、样本轴 0、fs=2000 Hz、样本区间 [0,20000)、通道 [0,1]，请求 2 Hz 网格和 50% 重叠，则 nperseg=1000。其余未知项省略。

```json
{"mode":"analyze","field":"data","sample_axis":0,"sample_rate_hz":2000,"nperseg":1000,"overlap_fraction":0.5,"start_sample":0,"stop_sample":20000,"channels":[0,1]}
```

真实配置替换为当前请求的值。analysis_max_samples / analysis_max_channels 限制的是所选区间的样本数和所选通道数量，默认分别为 262144 样本、4 路；不按源文件总样本或原始通道宽度填写。所选 90000 样本 × 3 路无需设置这两个预算，即使源文件有 21 路，也不能把 21 填成 analysis_max_channels。当前校验要求样本预算为正整数，没有固定样本数上限；通道预算硬上限为 16。超出默认预算时按请求显式设置或明确部分覆盖，不放宽上限、不静默改非法参数、不把示例区间套用到其他任务。

## 支持范围

- 支持实数数值 NPY、NPZ、传统 MAT、HDF5（包括 MAT v7.3 原始存储结构）、未压缩 PCM WAV（8/16/32 位）及 SWellEx 风格 SIO（id=10，int16/float32）。其他编码/类型明确报告不支持。HDF5/MAT 轴需确认，不自动按 MATLAB 习惯转置。
- NPY/HDF5/WAV/SIO 分块读取；传统 MAT/NPZ 有解码内存上限，超限报告。不会声称所有格式都支持流式读取。
- 交付可复现数据访问清单，不默认复制整个数组。统一视图为 [samples,channels]，保留原始值、dtype 和通道顺序并记录结构转换。
- 完整性/通道检查覆盖全部请求范围；基础分析有独立预算和覆盖记录，不能把抽样结论推广到全部数据。
- 几何仅核对坐标数、有效性与重复坐标；无同步/标定参考不能证明定位可用。
- 不静默补零、插值、删道、重采样、幅值归一化或滤波。不执行 CFAR、DOA、波束形成。未提供时间参考不能宣称检查了真实丢帧、重复帧或同步。

## 开发者验证（普通数据任务不执行）

修改脚本后运行 `python3 -m unittest discover -s <skill-dir>/tests -v`。验证多字段歧义、轴不明、采样率冲突、参数缺失、原始值不变、分块覆盖、异常定位、已知频率与功率尺度。读取器改动或明确的 Skill 验收还需独立片段对照，见 [开发者验收](references/acceptance-checklist.md)。结构校验不能代替行为验证。只解释结果或调整说明文档时，不因此重跑原始数据和完整分析。
