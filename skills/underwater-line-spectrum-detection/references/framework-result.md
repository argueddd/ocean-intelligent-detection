# 检测结果与按需交付 DetectionResult

状态：字段契约 0.1.0 已有 [Schema](../assets/schemas/DetectionResult.schema.json)、[待确认模板](../assets/templates/DetectionResult.draft.json) 和只读结构检查；已由 [runtime v1](runtime-v1.md) 生成公共结果及按需谱图/交付。参见 [框架范围](framework-v01.md)。

## 结果包公共内容

| 字段 | 内容与约束 |
|---|---|
| schema_version / run_id | 结果契约版本与运行标识 |
| request_ref / resolved_configuration | 本次实际请求、确认和参数快照或可核对引用 |
| task_results | 按 task_id 分别记录输入身份、detector_id/version、实现身份、状态、原因与输出 |
| coverage | 每项请求范围、实际已处理范围、排除范围及原因；使用原始时间映射，不拼接缺口 |
| candidates | 0.1.0 在各任务内直接记录候选列表；大表外置可作为后续版本扩展。未运行/失败使用 null，不能用空数组冒充零候选 |
| limitations / diagnostics | 已接受假设、输入限制、数值问题和算法适用边界 |
| artifacts | 请求产物与实际状态、依赖、保存定位和摘要 |
| association_ref | 已持久化关联记录的引用；未保存为 null，临时关联由会话持有，不承诺永久索引 |
| validation | 结构/数值一致性检查与算法效果/工程验收分别说明 |

run_id 不能取代 detector_version，schema_version 也不表示算法版本。请求与参数记录不能只保留原草稿，应说明实际生效值；没有任何新计算时不得创建伪造的已运行结果。

## 候选公共核心

| 字段 | 内容与约束 |
|---|---|
| candidate_id / task_id | 在本次运行内唯一，跨运行以 run_id 限定 |
| input_ref | 精确到来源包摘要与 signal_id，关联到真实波束或单阵元 |
| frequency | 点估计或区间、Hz单位、定义/估计方式；有网格时才提供频点索引，不虚构亚频点精度 |
| analysis_support | 作出判断所依据的样本/时间区间及原时间参考 |
| event_extent | 仅算法实际估计事件起止时提供，并注明定义；否则标明未估计，不能复制 analysis_support 冒充出现时长 |
| decision | 算法判定依据的小型说明/数值或有明确可用状态的证据引用 |
| measurements | 算法提供的量，逐项标明名称、定义版本、单位/尺度、数值和解释条件；允许无分数 |
| quality_flags | 确切限制或异常，不以一项通用“置信度”掩盖差异 |
| extensions | 算法命名空间下的额外字段，须由算法说明定义，不能覆盖公共字段 |

区间统一按相应时间参考解释，分析样本区间采用半开区间。不同候选不因频率接近就自动共用目标ID；同一候选在多个结果中的关系须由明确比较规则描述。

未标定不输出声压级。背景、门限、SNR、概率均非所有算法的公共必填项；某个分数即使范围在0到1也不天然是概率。不同定义的量不可仅凭列名相同或数值归一化就排名。

## 状态与解释

任务的 execution_status 使用 not_run、blocked、running、completed、failed；completed 且实际候选列表为空才可说明“本次条件下无候选”。缺少有效分析覆盖不是普通零候选成功，应报告无法执行/完成相应分析。

运行状态、产品交付状态和 quality_status 分别记录。程序完成不意味着真实线谱、目标、检测性能或工程验收通过。没有对应评价证据时明确未评价或证据不足；图像清晰、候选较多或两个算法一致不能代替真值验证。

批次分别显示各任务状态；有失败或未完成交付不能称全量成功。错误/中断产物不能发布成完成清单，也不删除其他成功结果。

## 计算 展示 保存三项选择

按照用户请求与算法产物声明核对依赖。缺失选择不推断为全选或全不选。算法必需的内部计算应在确认方案中说明，不要求全部写盘；额外绘图/分析所需计算不能隐藏成内部步骤。

每项产物记录 product_id、kind、归属任务、计算是否完成、是否可用、是否持久保存、来源/配置引用；数值矩阵还需轴、单位、坐标和有效性说明。保存文件使用明确包内位置和摘要；外部引用与实物打包分开。

状态至少能区分未请求、未生成、已生成且临时可用、已保存、曾生成但未保留/已不可用、失败。不能为了把状态补齐而额外生成未请求产物，也不能对未保存对象承诺持续可用。

不保存的选择不应暗中落盘完整谱矩阵或图集。显示所需临时文件/缓存应说明用途和生命周期，不作为永久产物；涉及磁盘写入时仍遵守所选临时策略。

## 最小持久记录

若用户保存候选表、单图或其他结果，随附足以解释该产物的输入身份/摘要、时间与单位、算法及版本、实际参数、未知决定、判据语义、覆盖/状态、必要关联和所选文件清单。不强制复制全部原始录音、波束权重、谱矩阵或未选图集。

如果用户只查看且不留存，使用临时结果并说明跨会话检索、补图或复算的限制。以后保存仍需结果尚可用且有明确请求；必要数据不可用时提出重新计算请求，不能偷偷重算。

已保存图若只包含视觉证据，应说明相应数值是否保存；缺失中间量不虚称完整数值可复查。候选的最低判据说明随已保存候选保留，详细中间量可以不保存，但不能只留下无法解释的悬空引用。

## 向独立评价模块交接

提供已有请求/配置、结果身份、候选判据、覆盖与证据可用性，具体语义见 [评价交接设计](../../underwater-line-spectrum-evaluation/references/evaluation-handoff.md)。检测结果的结构/来源核验不承担效果评价；quality/validation 不应填入没有证据的检测率、误报或工程通过。

按指标需求区分最终候选、单元级过门限判决与完整有效窗口。候选列表不能自动恢复成功零候选窗口或全部 H0 单元试验。0.1.0 中的聚合 coverage 不保证这些细粒度信息已经具备；没有足够证据时让评价报告不可算，不虚造记录、不无版本变更增加严格 Schema 未定义字段。runtime v1 在 resolved_configuration 中保存最小覆盖账本，完整单元矩阵/全组审计作为明确选择的 artifacts；不修改公共 Schema、不默认保存大矩阵。

评价输出分配独立身份，引用原 run/task/candidate 与来源，不改原候选、门限、确认和执行状态。未做评价时明确未评价；无真值的描述统计不能当成实际误报统计。

## 向频率轨迹模块交接

生产端规则与核验入口见 [跟踪交接](tracking-handoff.md)。交接不修改 DetectionResult 0.1.0，而是对一个明确、已完成的 `framewise` task 另建只读派生清单，绑定完整候选表、完整账本、resolved configuration 和最终 package manifest。

交接前必须证明候选未截断、零候选检测行保留、无效/跳过完整帧保留、候选行号与分析支持一致，并提供窗长、步长、NFFT、采样率、时间参考、频率网格及波束来源。只有平均谱、临时候选、未保存账本或只有图像均不足以形成轨迹输入；缺失时提出新产物/检测任务，不能偷偷补算。

交接仍只包含检测测量，不生成 `track_id`、谐波族、声源或目标身份。下游结果必须引用原 `run_id + task_id + candidate_id`，不得回写旧检测包。

## 验收要求

实现与验收检查：零候选与失败区分、时间支持不冒充事件持续时间、覆盖不漏报、不同算法扩展不冲突、无分数算法仍可接入、分数含义不混淆、持久产物最小出处完备、临时和外部证据可用性准确、未选大型产物不落盘。现有结构测试覆盖其中的状态、覆盖、身份及字段规则；实际产物/保存/数值核心已有合成回归，见运行入口；真实质量仍需专门证据，不能由格式检查宣称通过。


## 0.1.0 序列化说明

coverage、candidates、limitations、diagnostics、artifacts、quality 位于 payload.task_results[]；validation 单独表达记录所声称的检查。artifacts 的轴、坐标与有效性定义必须显式描述，不用文件后缀代替。当前 Schema 只支持候选内联；无分数可用 measurements=[]。

填写步骤、draft / specified 的区别以及 CLI 用法统一见 [字段结构与待确认模板](schema-validation.md)。结构有效不证明事实、确认或执行状态真实。
