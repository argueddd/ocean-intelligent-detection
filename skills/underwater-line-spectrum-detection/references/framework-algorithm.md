# 算法说明 AlgorithmDescriptor

状态：字段契约 0.1.0 已有 [Schema](../assets/schemas/AlgorithmDescriptor.schema.json)、[待确认模板](../assets/templates/AlgorithmDescriptor.draft.json) 和只读结构检查。新增 [固定 CA/OS 登记与执行入口](runtime-v1.md)；不提供任意代码路径/插件动态加载。参见 [框架范围](framework-v01.md)。

第一版已确认支持 CA-CFAR 与 OS-CFAR，可给建议但每次明确选择，不自动全算或切换；统计模型与数值参数仍待确认，见 [CFAR 设计与待确认项](cfar-design.md)。具体实现不把公共接口改成 CFAR 专用；只导出本机代码/依赖核对后的真实实现身份，不使用虚构摘要。

## 算法说明的目的

描述“能接受什么、需要哪些决定、会怎样处理、返回什么”，使公共层能询问、检查和交付。它不是一组用户已确认的参数，也不默认登记现有独立脚本。

不指定 Welch、STFT、背景估计或某种阈值作为公共必经步骤。通用数值工具将来可以复用，但每个算法必须申报实际使用步骤和参数，不能隐藏在库默认值中。

## 公共字段

| 字段 | 内容与约束 |
|---|---|
| schema_version | 说明文档契约版本，与算法实现版本分开 |
| detector_id / detector_version | 稳定标识及明确实现版本，不使用不固定的 latest |
| implementation_identity | 经明确安装/接入的实现引用与摘要；由受控登记解析，不从输入包执行任意路径代码 |
| input_requirements | 支持的 data_role、表示、数值类型、采样/长度条件、需要的元数据和对未知项的兼容条件 |
| capabilities | 支持的任务语义和输出范围；能力声明不自动扩大第一版已约定范围 |
| parameter_definitions | 算法参数的类型、单位、必填条件、约束、互斥/依赖关系、科学含义 |
| processing_definition | 预处理、分段、表示转换等步骤以及受哪些参数控制；允许不使用谱估计的算法 |
| result_definition | 候选频率和时间支持语义、判据含义、扩展字段定义 |
| product_definitions | 可提供的可选产物、依赖、坐标和单位定义、是否需额外计算或保存中间量 |
| resource_model | 与输入规模有关的工作量/内存/产物估算及估算限制 |
| limitations / validation_evidence | 适用边界、已有验证覆盖与证据；不能将文档存在当成效果验证 |

参数描述以 parameter_definitions.json_schema 表达类型和条件，使用 JSON Schema 的 required、if/then、dependentRequired 等表达必填/条件必填，不使用未定义的 required_if 关键字；可给建议及依据，但所有影响结果、解释、计算范围或资源的值，必须进入本次解析后的方案和确认。技术常量、随机过程/随机种子、数值精度若影响复现也要记录。未知字段、无效类型、冲突配置不静默忽略或强制转换。

嵌入参数/扩展 Schema 使用 Draft 2020-12 和本地 JSON Pointer 引用；不从说明文档加载远程 Schema 或任意代码。允许的子集及检查边界见 [字段结构说明](schema-validation.md)。单文档结构检查不匹配请求参数；新增 [preflight 0.1.1](preflight.md) 会将明确指定的请求参数逐项套入该 Schema，并核对声明的处理步骤、参数出处和产物依赖，仍不填充 default。该受限预检不是算法运行适配器或科学有效性证明。

## 处理与结果的申报

- 是否去均值、分帧、变换表示由算法说明，不因上游做过某一步就再次自动执行。
- 若算法使用窗口/频率网格，声明其参数和坐标定义；若不用，不强迫填写无关字段。
- 说明已知掩码或未知有效性是否满足算法条件；不能只接受数组然后丢弃有效性元数据。
- 说明频率输出是点估计、网格位置还是区间，时间字段是分析支持还是事件估计。
- 背景、门限、显著性、概率或任意分数只在算法确实提供时出现；单位、定义和适用条件齐全。统一归一化不使不同统计量变得可比。
- 不得将自动选束、跨束目标归并或隐式补算包装成内部实现细节。新增能力必须另行纳入范围并确认。

## 调用职责

下列名称表示职责；本版实际函数/CLI 分别落在 cfar_registry、detection_runtime，详见运行入口：

1. describe：只提供说明，不做检测。
2. validate_request：检查输入、参数、未知项决定、输出依赖和资源；返回明确问题，不试跑检测挑选参数。
3. execute_confirmed：仅接收公共层核对后的确认配置及只读输入，返回公共结果与声明过的扩展；不擅自写原数据或上游结果。

调用仍须由公共层守住确认边界，不能仅凭算法自行返回 can_execute=true 就运行。算法未登记、版本不可获得、任务不支持或参数未定时停止；不自动替换另一实现。preflight 仍只实现声明/文件层子集；cfar_registry 和 detection_runtime 提供真实说明与算法专属门禁/执行。纯文字科学约束不能代替核对实现；仍不允许旧命令冒充新协议。

## 新算法接入步骤

明确用户要求的算法与边界后，再编写说明、参数 Schema、数值实现、公共结果映射、可选产物和测试。测试既验证算法效果，也验证掩码、来源、参数确认、失败状态和接口语义；独立脚本的旧测试不自动覆盖新适配器。

版本变化保留旧运行记录。不能在接入时把演示参数、合成测试的 MOCK 确认或常用阈值写成实测默认授权。没有具体算法也能完成框架设计，但不能生成虚构检测结果。


## 0.1.0 序列化说明

AlgorithmDescriptor 不要求谱估计步骤或统一分数；参数和扩展 Schema 不等于已注册插件。implementation_identity.registration_key 是受控登记键，不是待执行代码路径。

填写步骤、draft / specified 的区别以及 CLI 用法统一见 [字段结构与待确认模板](schema-validation.md)。结构有效不证明事实、确认或执行状态真实。
