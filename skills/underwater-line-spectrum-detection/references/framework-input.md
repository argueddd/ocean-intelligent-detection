# 统一输入 SignalInput

状态：字段契约 0.1.0 已有 [Schema](../assets/schemas/SignalInput.schema.json)、[待确认模板](../assets/templates/SignalInput.draft.json) 和只读结构检查。主/旁路完整交接包到此对象的 [适配器 0.1.0](input-adapter.md) 已实现自动提取与逐字段来源核对，复用旧接收器的数值有限性/掩码一致性检查。preflight 0.1.1 可显式开启适配核对；不启用时仍只检查明确绑定文件的摘要与 NPY 结构，见 [预检边界](preflight.md)。按 [框架范围](framework-v01.md) 理解通用语义；本文不扩张既有文件格式支持。

## 输入路径

第一版公共入口以有明确身份的时域信号为主。主波束结果经 [既有交接](beamformed-input.md) 的 receive/load_beam 接入；单阵元或外部已有波束经该文档的旁路段接入。使用旁路前还须阅读同级 underwater-beamforming 的 references/bypass-handoff.md。

这些入口目前提供只读 float64 [sample,1] 波形、元数据与有效性信息。公共层不得重新猜裸 NPY/WAV/SIO 的身份、接收原始多阵元后偷偷展平，或从谱图恢复波形。未满足接入条件先返回上游读取检查流程。已有 PSD/时频矩阵可作为关联证据，但不是本版时域主接口的替代输入。

## 公共字段

| 字段 | 内容与约束 |
|---|---|
| schema_version | 文档信封中的字段契约版本；当前为 0.1.0，不复用上游交接版本 |
| source_package | 清单定位、已核对摘要、包种类和上游契约版本 |
| signal_id | 包内原有信号标识；与 source_package 摘要共同限定身份 |
| data_role | 保留 single_sensor 或 beamformed；角色未知不能靠列数推断 |
| waveform | 包内文件定位、内容摘要、dtype、shape、轴定义与样本数；引用原数据，不复制变换后的假原始数据 |
| sample_rate_hz | 有依据的正有限数；缺失阻断需要 Hz/时间对应的检测 |
| time_mapping | 输出样本0对应时间、时间参考、与原始样本的映射及出处；不伪造 UTC |
| validity | known/unknown 状态、掩码或区间引用、具体含义及上游检查限制 |
| units | known/unknown 状态、原单位与幅值约定；未知不填声压单位 |
| frequency_coverage | 上游实际处理/保留频带及活动频点信息或明确 unknown；不是本次搜索频带 |
| processing_history | 已执行步骤及完整上游配置的可核对引用；不将记录当作物理验收 |
| beam_source | 波束算法、beam_id、保存列与扫描列、完整方向定义、上游 result 引用；单阵元为 not_applicable |
| limitations | 未验证的同步/标定、名义模型、临时映射等事实与限制 |
| provenance | 原始来源和交接链；哪些证据在包内、哪些只有外部引用 |

适配层保留完整来源对象的可核对引用；无需为本文字段重新编造上游缺失的信息。beam_source 中的波束算法与 DetectionRequest 中 detector_id 分开，外部波束算法未知不得填 CBF。

## 时间与有效性

样本区间使用输出数组坐标的半开区间 [start,stop)，满足 0 <= start < stop <= N；原始样本区间另行标识，不能混用。用户以秒选择范围时，需要声明如何映射到实际样本并记录实际覆盖，不静默改变请求范围。

主交接掩码按原含义继承；旁路的 validity=unknown 保持未知，不能生成全 true 或全 false。已知无效样本不删除后拼接。分析范围作为请求中的选择，不改写输入；被选算法应申报如何使用有效性、如何定义实际分析支持区间。

关于未知有效性/频带的用户决定见请求规范。仅允许传输未知项的旧确认，不授权未知条件下的检测；无法形成合法算法输入时即使“先试试”也不能运行。

不要求单阵元提供声速、阵列坐标或波束权重；方向未知是否阻断某项工作取决于该工作实际要求：不能定位方向的比较必须受阻，不能因此伪造方向让检测或比较继续。

## 一致性与只读

优先核对现有清单、编码、形状、来源配置和内容摘要；不偷偷纠正冲突。运行前及发布结果前核对消费来源未变。只读内存映射不保证其他进程无法修改源文件。

单个包多个信号分别生成输入身份；不同包即使 signal_id 相同也不是同一信号。一个批次不默认全选、不自动求共同掩码或合并时间轴。

可移植包不要求原机器绝对路径仍存在；依赖未打包的源文件/谱图时必须说明，缺失仅阻断依赖它的动作，不能把路径字符串当作实际已具备的证据。


## 0.1.0 序列化说明

SignalInput 的业务字段位于 payload；validity 允许明确未知，或已知区间/掩码引用。方向用 known/unknown/not_applicable 状态对象，已知方向必须含坐标约定；这些声明是否符合真实上游数据不由结构检查证明。

填写步骤、draft / specified 的区别以及 CLI 用法统一见 [字段结构与待确认模板](schema-validation.md)。结构有效不证明事实、确认或执行状态真实。
