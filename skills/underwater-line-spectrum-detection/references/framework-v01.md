# 线谱检测公共框架范围与实施边界

状态：公共范围与字段契约 0.1.0；基础 preflight 0.1.1 与 input_adapter 0.1.0 保持只读/交接边界。CA/OS 检测运行实现 1.0.0 已接通谱、门限、候选、交付与三层波束协作，见 [执行入口](runtime-v1.md)。设计支持、程序完成、实测效果及工程验收分别报告。

## 职责与六项工作

公共层组织输入、确认、调用、结果和波束协作；算法层申报并实施计算；展示层按请求查看与交付。检测负责“按什么规则找出候选”，独立 underwater-line-spectrum-evaluation 负责“这些结果表现怎样、证据是否充分”。共同目的为后续目标判断提供可追溯证据，不在第一版自动确认目标。

| 工作 | 第一版职责 |
|---|---|
| 输入接收与核对 | 明确信号、时间、有效性、来源和上游限制 |
| 检测方案与参数解析 | 算法与任务要求明确后推导可逆设置；仅将无法裁决的核心歧义汇总询问 |
| 功率谱与时频谱计算 | 只在所选算法或另行确认的分析需要时进行，不强制某种谱估计 |
| 线谱候选检测 | 调用明确选择的算法，保留方法特有判据；已接入 CA/OS 系数、谱处理、逐点判断、候选生成和确认执行器 |
| 时间分布与统计 | 记录实际分析覆盖、逐窗状态或可核验等价信息及候选数量摘要；正式评价统计归评价 Skill，不暗中加入跨帧轨迹关联 |
| 结果保存展示与核验 | 按需交付并核对结果结构/来源/数值一致性；效果评价与工程验收归评价 Skill |

多条时域信号按明确选择分别处理，不在公共层自动融合、选束、选择检测器或合并目标。只看已有产物不授权新数值计算；为显示需要补谱也属于待确认的计算。

## 五类接口

| 对象 | 完整规范 | 责任 |
|---|---|---|
| SignalInput | [统一输入](framework-input.md) | 上游适配形成，公共层核对 |
| AlgorithmDescriptor | [算法说明](framework-algorithm.md) | 经明确接入的算法实现提供 |
| DetectionRequest | [请求与确认](framework-request.md) | 用户意图与处理决定形成，公共层核对 |
| DetectionResult | [结果与按需交付](framework-result.md) | 算法返回数值，公共层汇总状态与来源 |
| AssociationRecord | [关联与协作](framework-association.md) | 公共层建立受控双向索引及追加请求 |

五种对象采用 schema_version=0.1.0 的独立 JSON 文档，共用版本化定义；业务字段放在 payload 中。模板为 draft，所有业务字段留空并附待询问记录，不是可运行请求。不能传给既有交接/检测脚本；不将待定项补成默认值。字段/序列化约束以随包 Schema 为准，科学语义仍须遵守对应规范。

## 通用语义

- 区分事实、用户选择、假设与未知。待定值不能当成零、空数组、全频带、全时间或全有效；明确空列表才表示“明确不选择”。不适用与未知分开。
- 标识在所属包/运行内唯一；跨包使用包摘要与对象ID的组合，不以文件名、列号或角度单独判断身份。路径负责定位，摘要与来源信息负责一致性，不把摘要当作物理真实性证明。
- 文件引用应说明所在包、相对路径或外部定位及摘要；持久包内保存的引用不得越界。外部引用不得冒充已打包文件，缺失就报告。
- 只在用户置于范围内的来源查找信息。无法确认的信息必须报告或询问，不默默选择“最可能”的版本。
- 各信号保留完整时间对应，选取分析范围不授权重写原文件；没有绝对时间就只报告已有相对时间。
- 参数/输入就绪、用户确认、运行完成、产物保存与质量验收是不同状态。不用一个 completed 覆盖这些含义。
- 计算、展示、保存分别选择；最小追溯信息随已保存结果交付，大矩阵/图集不默认生成。临时结果没有永久可用承诺。

## 与既有实现的关系

保留 [既有交接入口](beamformed-input.md)、请求模板及全部脚本。上游的 prepared/accepted/can_detect=false 继续仅描述交接，不因新增文档改写。新检测任务另有请求、确认、运行和结果记录，不修改旧清单。

现有 line_spectrum_methods.py、line_spectrum_metrics.py 是独立工具，不是新框架插件。它们的默认参数、示例、接收能力和既往测试不能充当新框架确认或验收证据。方法知识仅在用户明确进入方法设计/分析任务后按 [方法参考](methods.md) 使用；已有结果的效果评价转 [独立评价 Skill](../../underwater-line-spectrum-evaluation/SKILL.md)，不能因此自动添加算法、指标或实验。旧 metrics 的 psd/lofar 包含检测，且旧真值/分母处理不满足新的证据规范，不得直接充当评价执行器。

## 第一版协作与排除项

第一版包含双向索引、按需联合查看与比较、经确认进一步计算三个层次的设计与显式运行入口，见关联规范。算法自身可提供什么信息，由能力说明表达，公共层不要求所有算法具有相同中间量。

公共层不默认选用具体检测器或谱参数；当前第一版方法设计见 [CFAR 设计与待确认项](cfar-design.md)。仍不加入自动选目标/波束、方向或频率轨迹跟踪、谐波归并、DEMON 执行、自动目标身份判定、实时处理、跨阵相干合并或自动反馈循环。既有研究工具仍保留，不等于这些能力已进入公共执行框架。

## 后续实施与验收范围

字段 Schema、待确认模板、输入适配和受限预检保持原边界；新 [运行入口](runtime-v1.md) 增加固定算法登记、完整上游核对、有效帧/科学约束、执行确认、来源复核和按需结果。CA/OS、q/M、H0 最大值标定与候选规则已实现，具体参数须逐次解析并记录来源；可逆设置不要求用户逐项确认。结构合格不证明科学模型或真实授权；不使用旧研究脚本冒充新框架。

公共框架验收应覆盖：缺参或冲突阻断、来源变化阻断、不同包同名信号不混淆、未知掩码不补齐、跨缺口不拼接、算法版本与确认绑定、失败与零候选区分、批量部分失败不报全成功、分数语义不混比、反向索引可回溯、缺失关联不替换、追加请求不自动执行、只展示不偷偷补算、未请求产物不批量保存。

整链路合成回归见 [运行验证范围](runtime-v1.md)，结构测试仍只证明自己的范围。真实算法效果和工程验收仍需另行明确真值、指标、场景及验收条件。

## 独立评价交接

评价接口的语义设计见 [评价交接](../../underwater-line-spectrum-evaluation/references/evaluation-handoff.md)。保留五类现有契约的版本与脚本，不把该设计当成新字段/API；逐窗有效覆盖、单元级判决或真值覆盖等额外证据须按所选指标另行明确，缺失时报告不可算。评价结果与原检测结果分开保存，通过原身份相互引用；不回写或重跑旧结果。

平均候选数不是平均误报数；无真值、局部标注或无可信背景不能自动获得误报判断。检测阶段仍负责 CFAR 门限设计与标定，评价阶段核验独立证据；用户已确认第一版支持帧级或整段至少一次误报的事件概率，每次明确选一种；每条输入信号与检测算法分别控制，联合控制后置，平均误报数量作为评价而非第一版门限目标。原始超门限事件、均分预算及最终候选筛选规则已明确；具体 q、模型与本次运行选择仍需确认。
