# 参数确认与计算门禁 v0.1

适用于 [数据契约](data-contract.md) 中的输入、物理模型、算法设置和输出解释。本页保留总体确认规则；v0.2 逐组确认见 [预检查接口](preflight.md)。v0.3 受限数值入口还要求 [数值执行接口](numerical-execution.md) 中的独立数值配置和范围确认，不能由旧预检查报告直接授权。

## 1. 核心规则

先区分数据/物理事实与可逆处理选择。输入身份、采样率、阵列几何和映射等事实必须有来源；算法初选、窗长、重叠、网格密度、加载策略、输出和资源预算等处理选择可以依据任务与数据自主决定。只有缺失事实使核心计算不成立、来源冲突无法裁决或所有保守方案都不可执行时才询问。

已有明确、可核验且无冲突的来源事实直接引用；引用时记录来源和适用对象。新增近似、算法选择和范围变化若可逆，可按 Skill 基线或数据推导采用并记录为 Harness 决策；不得把任意文件字段解释成所需事实。

决策可以是一个具体数值，也可以是边界明确的自适应规则。执行规则时记录实际采用值及触发条件；超出规则范围时先选择保守退化方案，只有退化后核心目标仍无法完成才询问。

“分析一下”“开始吧”“你看着办”“先试一下”等任务请求授权自主解决可逆处理选择，但不授权伪造缺失物理事实。记录中区分用户提供事实、来源事实、确定性推导和 Harness 自主设置。

## 2. 已确认的项目级要求

这些要求来自本 Skill 的需求确认，可沿用；不能扩展为某次实测的数值参数：

- 方法范围仅 CBF、MVDR；未指定时按 SKILL.md 的自主基线选择。
- 时域是下游主要接口，但不默认保存全部方向。计算方向与保留方向独立记录，按任务链和预算选取保留列表；用户请求的全方向谱和图也属于正式结果。
- 支持指定一个/多个方向和显式请求的固定网格扫描；无方向/模式先问。
- 不自动找目标、不自动选波束、不进行目标跟踪。
- 谱产物可显式单选或组合，不默认整套生成；单角度不自动删掉用户请求的角度图，网格扫描也不自动增加未请求的图。
- 未知物理事实不猜测；可逆参数依据数据或 Skill 基线自主确定，禁止静默删道、改写源数据或把假设表述为实测事实。

窗长、网格、声速、阵列近似、MVDR 正则化等尚未被项目级确认；不得从其他 Skill 的默认设置自动继承。

## 3. 参数确认记录

每个会影响本次计算的参数或紧密关联的参数组，用以下结构记录：

| 字段 | 说明 |
|---|---|
| `key` | 参数/参数组的明确路径 |
| `kind` | `fact`、`model_assumption` 或 `processing_choice` |
| `status` | `unknown`、`proposed`、`confirmed`、`conflict` 或 `not_applicable` |
| `value` / `rule` | 实际确认值或有边界的规则；未知为 null；建议值与确认值分开 |
| `evidence` | 用户明确陈述、文件元数据字段、文档位置、已有配置及其适用依据 |
| `confirmation` | 用户确认内容与可核验的消息/记录引用；不要伪造时间戳、消息 ID 或签名 |
| `scope` | 适用数据身份、源版本、通道、范围、算法及配置版本 |
| `impact` | 缺失/冲突会阻断哪个阶段，允许继续什么 |
| `resolved_value` | 使用已确认规则时实际得到的值、触发依据与范围 |

`confirmed` 必须有依据，不能把假设冒充来源事实。对于处理选择和明确标为 nominal 的模型假设，本项目用户已授权 Harness 自主决定，可把真实任务请求和 `harness-autonomy-v1` 规则记作 `confirmation.method=user` 的项目级授权引用，同时在 evidence 中记录推导或基线依据；这不表示用户逐项提供了数值。`not_applicable` 需说明理由。参数可由来源事实确定性推导，例如 fs 和样本数推导时长；记录公式和来源，不借此推断采集连续性。

源文件、通道选择、几何映射、方向定义或计算设置变化时，检查受影响确认与既有结果是否失效；不盲目复用上一轮确认。mtime_ns 等大整数必须无损保存，不能经 JavaScript Number 舍入；门禁报告源变化时先查证，禁止改源时间戳迎合清单。

## 4. 计算前必须解决的类别

按实际分支要求，不向已有波束旁路输入索要无关原始阵列参数。

| 类别 | 原始阵列波束形成前的确认内容 |
|---|---|
| 数据身份 | 文件/字段、轴、阵元而非波束、采样率、原始值与处理历史 |
| 请求范围 | 源样本区间、选定阵元、算法列表、处理及输出频带 |
| 物理模型 | 几何与映射、坐标系、声速、传播模型、方向/时延参考 |
| 同步与标定 | 可用证据、未知事项及其明确处理决定；不能把数据质量相关性当同步证据 |
| 方向 | 指定方向或网格模式、角度含义、完整方向/网格定义 |
| 公共处理 | 是否去均值/滤波/归一化、窗与帧设置、边界/频带外策略、数值精度 |
| CBF | 加权/加窗、归一化、参考及补偿方式 |
| MVDR | 训练数据、快拍与估计规则、更新规则、加载策略、稳定性判据、失败处理 |
| 输出 | 时域保留方向（未指定先问）、时间对齐与有效区间规则、谱/图的窗、频带、尺度、归约与显示规则、存储规模与新目录 |

“未标定”“不加载”“不预处理”“保留 unknown 单位”都应是有依据的状态或显式记录的自主处理选择，不是伪造的来源事实。

未知绝对单位时默认进行原始单位下的相对分析并保留 unknown，不输出声压级。未知同步证据时直接在明确 assumed 限制下做探索性结果，未知标定使用 uncalibrated/none；无实测声速时探索性任务使用 1500 m/s 并标为 nominal assumption。这些基线不再单独询问。几何或映射缺失且无法从绑定契约取得时阻断阵列导向计算。名义模型必须标为 nominal/assumed，不能写成实测确认。

## 5. MVDR 的附加约束

- 训练数据来自当前处理片段、独立区间还是外部记录，必须明确。不能自动指定“最安静”的片段为纯噪声。
- 明确协方差估计的时间范围、帧/频率聚合、是否中心化、快拍定义、更新周期和非平稳数据的处理方式。重叠帧数量不等于独立快拍数量。
- 对角加载需明确是否使用、绝对值还是相对尺度、计算公式及系数；不能把库的默认加载量或“常用值”直接代入。
- 数值稳定性阈值、最小可接受数据量、奇异/病态矩阵处理及权重异常处理，需确认值或规则，不凭固定通用阈值宣布可靠。
- 遇到病态矩阵时，不擅自改用伪逆、提高加载、改变快拍范围、减少通道或回退 CBF。已确认应急规则存在时可以执行，但实际动作和影响必须留痕。
- CBF 与 MVDR 对比使用相同公共输入与处理范围；某算法失败不能替换标签，也不能只展示成功结果而隐藏失败。

## 6. 允许先做什么，必须暂停什么

物理事实不足时允许：只读列举文件/字段/形状/已有元数据；核对证据冲突；完成不依赖该事实的检查；整理问题和候选方案；在已有范围下估算资源需求。可逆处理项不因缺少逐项人工确认而阻断。

确认前禁止：依赖未知参数生成导向矢量、协方差、CBF/MVDR 结果、重建信号，以及以候选模型生成具有实测含义的图或指标。禁止隐藏的试跑、参数扫选或将预检查偷偷变成正式分析。

某个独立分支已具备条件时先运行并交付该分支。例如 MVDR 条件不足而 CBF 完整时先完成 CBF，同时明确两者对比尚不完整；不要让一个分支的缺失阻断全部任务。

文档编写、代码开发与模拟测试不需要猜填实测参数。合成测试的参数应明确标为测试夹具，不能混入实测配置；也不能把合成验证称为 SWellEx-96 验证。

### 询问格式

确需用户输入时只提问一次，先完成不依赖答案的工作，再用一个“需要你确认”清单汇总当前全部阻断项：

1. 目前知道什么，证据是什么。
2. 缺少或冲突的具体参数。
3. 该参数影响哪项计算或解释。
4. 可选处理方式及各自限制，并给出推荐项。
5. 请求用户选择；允许回复“按推荐执行”。未回答时只保持依赖这些事实的步骤阻断。

不要把可自主决定的工程参数放进清单，也不要拆成多轮逐项追问。只有出现此前无法通过探查发现的新物理冲突时，才可在用户回答后补问一次。

## 7. 状态与异常

参数未明确时报告 `parameter_status=needs_input`；冲突或无效值为 `invalid` 并说明问题。门禁有三个独立条件：参数已解决、执行实现可用、本次范围已获授权。任何一个未满足都不进入数值处理。

v0.2 预检查入口即使通过，can_execute 仍为 false；它不执行算法。v0.3 execute.py 具有独立受限门禁，check 通过也不等于 run 成功。只有确实完成计算与保存才报告 execution_status=completed，不得伪造结果或确认。

计算中超出已确认规则时停止受影响工作，保存真实完成范围和诊断。不覆盖源文件或既有结果；不以零值替换坏段、不静默删除失败波束、不压缩时间轴、不放大波形来掩盖衰减。

仅当用户事先确认失败后可交付部分结果，才将明确标记的有效子集交给下游；否则报告失败/部分完成并等待处理决定。参数齐全、文件生成和工程质量通过是不同结论。

## 8. 行为测试场景与覆盖

以下是整体行为要求。v0.4.3 已实际重新运行原160项测试及新增32项功能/命令行测试，上游读取检查另59项通过。按需谱组合、导入、旁路、子集补图和数据交接的具体覆盖见 acceptance-v043.md。S59 VLA 首60秒受限实测回归与数据链路已通过；水平阵映射、未实现策略及物理工程验收仍未完成，线谱检测不属于本模块。禁止把测试通过或单个真实片段视为所有数值能力和实测均通过。

| 场景 | 预期行为 |
|---|---|
| 多通道但身份不明 | 询问阵元/波束身份，数值核调用次数为零 |
| 多条已形成波束 | 不调用阵列波束形成，保留 beam ID |
| 未给方向和模式 | 询问，不能默认扫描 |
| 已要求扫描但缺间隔/角度参考 | 列出缺失项，不自动补网格 |
| 只给阵元深度 | 不静默填零生成横向坐标；询问模型 |
| fs 有两个冲突来源 | 暂停依赖 Hz/时间/导向的计算，等待明确解决 |
| 旧配置带分析默认值但本次未确认 | 标为候选而非已确认，不进入算法 |
| MVDR 未给训练/加载规则 | 询问；不调用默认值，不回退 CBF |
| MVDR 病态且无已确认应急规则 | 停止受影响计算，保留诊断并询问 |
| 用户已确认范围明确的加载规则 | 在规则内执行并保存实际值；越界则暂停 |
| 网格结果超过预算 | 报告预计资源并询问，不只保存最强波束 |
| 明确只生成谱和图 | 不写时域文件，不声明时域交付完成，也不声明下游就绪 |
| 未指定时域保留方向 | 按下游任务与资源预算自主选择；只需空间/谱评价时可不保存，线谱下游保留所选波束 |
| 更换源文件或通道映射 | 重新检查相关确认有效性，旧结果不得冒充新结果 |
| 仅持预检查报告请求立即运行 | 说明该报告不是执行授权；使用 v0.3 独立门禁，缺参数或不支持时停止，不伪造产物 |
