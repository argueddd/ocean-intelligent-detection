# 波束形成数据契约 v0.1

当前输出策略以 [结果输出与展示及子集补图](output-products.md) 为准：谱种类显式单选或组合，主计算每种所选谱覆盖全部计算方向，后续补图可显式选择已保存子集；时域仅保存明确指定子集，未指定先问。本文其余部分保留整体输入输出设计。v0.2 清单检查接口见 [预检查接口](preflight.md)；v0.3 已实现受限的 CBF/MVDR、时域重建及保存，具体数值字段、文件名和当前限制见 [数值执行接口](numerical-execution.md)。本文的逻辑字段表不是可直接传给检查器的完整 JSON Schema，也不代表总体设计的每项能力均已实现。

## 1. 范围与基本约定

- 与现有检查模块对接的第一版入口为实数时域波形。复数基带输入需另行明确载频、频率轴和输出约定，本版不静默接收或取实部。
- 标准输入视图 `x[sample, channel]`；已保留时域输出 `y[sample, retained_beam]`。单通道/单波束也保留第二维，禁止凭尺寸推断物理含义。
- 输入保持原始通道顺序及来源索引；必要结构转换需基于明确轴信息并记录。不能自动排序阵元以“修正”映射。
- 样本索引采用零基半开区间 `[start, stop)`；频率记录为 Hz，采样率为 Hz，时间为 s，几何长度为 m。只有源单位明确时才能换算，并记录换算。
- 角度数值记录为度，但零方向、正方向、坐标系和表示方式必须单独定义，不能从度数推断。
- JSON 不使用 NaN/Inf；未确认项用 `null` 并关联问题记录。`null`、缺失、0 和“未执行某处理”不可互换。

## 2. 输入描述

0.4.2 新增 [读取检查交接适配器](inspection-handoff.md)：读取已有0.2报告、经明确确认导出NPY、生成待确认配置，并把来源和检查覆盖绑定到执行器。此路径已通过 v0.4.3 合成及 VLA 回归；不是根据报告 completed 自动计算。

0.4.3 新增 [单阵元/已有波束旁路交接](bypass-handoff.md)：消费上述已完成导出包，按明确选择传递真实角色、完整时域轴和来源；未知算法/方向/频带/有效性必须先确认如何处理，不默认为正常。它不执行波束或检测，已通过 v0.4.3 合成旁路与接收测试。

波束形成配置独立于旧版数据检查配置。输入可以是文件、经明确选择的文件字段或读取器提供的访问视图；禁止把下表新增字段直接传给只支持旧配置键的读取器。

| 字段 | 内容与约束 |
|---|---|
| `schema_version` | 本节逻辑契约版本 `0.1`；实际预检查配置使用独立的 `0.2` 轮廓，见 preflight.md |
| `source` | 文件/数据来源、字段选择、字节数、mtime、可用的内容哈希；大小和时间戳不得冒称内容哈希 |
| `representation` | 本入口为 `time_waveform_real`；其他表示报告不匹配 |
| `data_role` | `sensor_array`、`single_sensor`、`beamformed` 或尚未确定的 `unknown`；需证据 |
| `axes` | 源轴顺序、标准轴顺序、已确认的结构变换 |
| `shape`、`dtype` | 源形状与类型、读取视图形状与类型，不改写源值 |
| `sample_rate_hz` | 有来源的有限正数；与文件或说明冲突时先解决 |
| `sample_range` | 本次读取的源样本区间和源总样本数 |
| `time_reference` | 源时间原点、是否仅为相对时间、采集时间参考；不得伪造绝对时间 |
| `channels` | 每列的源索引、稳定 ID 和身份；传感器用阵元 ID，波束用 beam ID |
| `units` | 已确认单位，或保留 `unknown` 并记录用户允许的使用范围 |
| `processing_history` | 已知的滤波、重采样、标定、波束形成等历史；未知不能写成“未经处理” |
| `inspection_evidence` | 可用的检查报告、来源关联、实际覆盖及未检查项 |
| `parameter_records` | 指向参数确认记录，格式见 [确认规则](parameter-policy.md) |

### 分流条件

- `sensor_array` 至少有两个确认对应不同阵元的通道；只有一个时不能伪装成阵列输入。
- `single_sensor` 可以交给时域线谱分析，但不得标注“波束增强”。
- `beamformed` 的每列是波束，无论一列还是多列都不进行二次阵元波束形成。
- `unknown` 或多源含义不清的通道集合必须询问；同样采样率、长度相同或相关性较高不证明属于同步阵列。
- 已有波束的历史指向不明时，先说明能否按匿名波束做频率分析并询问；不得将方向填为 0°。线谱分析不需要重新提供原阵列所有几何，但其缺失会限制波束评价。

## 3. 原始阵列专用元数据

只对本次需要实际波束形成的原始阵列要求这些条件；旁路交接不强制补齐无关阵列参数。

| 字段组 | 必须明确的内容 |
|---|---|
| `geometry` | 与选定通道一一对应的 `[channels, 3]` 米制坐标、坐标系、原点、各轴方向、参考位置、坐标来源和实测/名义模型身份 |
| `propagation` | 声速数值及来源或已确认规则；平面波/其他传播模型及适用范围；近似及用户接受记录 |
| `synchronization` | 同步依据、共同时间轴、已知时延及是否已补偿；未知状态的处理决定 |
| `calibration` | 幅相标定状态、适用通道/频率、可用系数及用户决定；不等同于绝对物理单位确认 |
| `channel_selection` | 明确使用的源通道 ID、索引及顺序；任何剔除要有原因和确认 |

只有深度或一维位置时，不将缺失的横向坐标自动填零。可在项目级自主授权下采用明确标为 nominal 的一维线阵模型；原测量事实仍保留缺失状态。未知同步/标定可作为明确的 assumed/uncalibrated 探索性限制，但不能改写为“已验证正常”。

不同阵型允许解释的方向不同。对线阵的阵轴夹角或锥角，不静默解释为唯一地理方位；需在方向定义中说明限制。

## 4. 运行请求

以下是配置的逻辑分组；具体数值以及影响结果的规则都需按参数确认规则解决，本文不提供可直接用于实测的默认值。

| 分组 | 必须表达的选择 |
|---|---|
| `algorithms` | `cbf`、`mvdr` 或二者的显式唯一列表；支持两者不等于每次运行两者 |
| `direction_plan` | 模式、方向参数化、坐标系、方向列表或完整网格定义 |
| `processing` | 请求时间段、输入通道、处理频带、预处理列表（不处理也显式记录）、数值精度 |
| `transform` | 采用的实现域；频域实现所需窗函数、窗长、步长、FFT 长度、谱约定、填充和边界处理、合成窗/逆变换约定 |
| `cbf` | 阵元加权方式、权重归一化、延时/相位补偿的参考和符号约定；相关算法配置 |
| `mvdr` | 协方差数据来源/范围、估计与更新规则、快拍与重叠约定、加载/正则化策略、稳定性判据和失败处理 |
| `output` | 新目录、时域交付范围、文件组织、幅值尺度、辅助产物选择、权重保存/复现方式 |

源信号未知信息和处理选择分开记录。SWellEx-96 只是验证数据来源，不是全局参数模板；不得套用某次采样率、声速、几何近似、窗长或网格。

### 方向模式

`specified`：显式的一个或多个固定方向。每个方向拥有唯一 `beam_id`；顺序与用户确认的列表一致。

`grid`：目标未知且任务要求搜索时可自主选择。各角度轴范围来自方向坐标的有效域，间隔按阵列角分辨率和预算推导，端点、排列顺序及单轴/双轴定义写入请求；不能在执行时静默四舍五入端点、去重或改变间隔。网格方向在整段处理期间固定。

每个方向需记录 `parameterization`（如 `azimuth_elevation` 或定义明确的 `array_angle`）、角度值、角度参考框架和正方向。不能假定 0° 总是正北、阵列正侧向或水平。

缺少目标方向时按任务采用受控网格扫描；方向坐标语义无法从几何契约确定时才询问。不从强谱峰伪造真实目标方向。CBF 与 MVDR 做对比时保持同一输入范围、方向列表及公共处理条件；算法特有参数分别记录。

### 频带和时域合成

频域实现在计算中保留复数波束系数，按已确认的窗、步长、尺度与边界规则逆变换并合成时域波形。功率谱、取模结果和空间谱不能替代相位信息。

必须明确频带外数据如何处理；补零频带、保留某路输入或切换另一算法都会改变信号，不得默认采用。若只保留选定频带，结果标为带限波束信号，不能称为全频带。

算法性边界填充需与原始采集缺口补零严格区分。保留必要的上下文、填充与裁剪记录，标注受边界影响区间。实际时间对应关系必须可还原，不能为了长度一致而静默拼接不连续片段。

针对实数输入的频域重建需正确处理正负频率关系及 DC/Nyquist 边界；不得用任意丢弃虚部掩盖实现错误。频域/子带实现方式仍须在开发时明确，不把本节写成某库默认配置。

## 5. 条件输出：已指定保留方向的时域结果包

实现时使用新目录；以下是预定文件布局，不代表这些计算文件已经生成：

```text
run-directory/
  result.json
  parameter-records.json
  report.md
  cbf/                       # 仅在请求 CBF 时创建
    waveforms.npy
    metadata.json
  mvdr/                      # 仅在请求 MVDR 时创建
    waveforms.npy
    metadata.json
```

本节旧示意布局不是 v0.4/0.4.1 的实际文件清单；现行文件名、纯谱任务及列映射见 output-products.md。NPY 为本契约的无损数组交付格式约定，JSON 为元数据格式；它们不是物理参数默认值。仅保存数值数组，不使用 object/pickle。不默认导出会量化、截幅或重标度的 PCM WAV。

- `waveforms.npy` 为实数浮点二维 `[samples, beams]`，单波束保持 `[samples, 1]`。元数据记录实际 dtype 和精度选择，不隐式降低精度或峰值归一化。
- 每个算法仅为明确指定保留的方向生成时域文件；明确不保存时不生成。全部计算方向仍应有本次请求的谱结果。大数据可分片保存，但必须有清单记录算法、beam ID、全局样本区间及拼接次序；下游不得猜测拼接。
- 若存储/计算超预算，先报告可选方案并询问；不自动只保存最强波束、只存图片或缩短数据。
- 未运行的算法不创建伪结果目录。失败的波束或区间不能用其他算法填充并保留原标签。
- 允许用户预先确认“失败后保留已完成部分”，但必须标为 `partial`，列出未完成范围，不能交付为完整结果。

### 每个算法的 metadata.json

| 字段 | 内容 |
|---|---|
| `schema_version`、`algorithm` | 契约版本和实际算法，禁止混用标签 |
| `data_role`、`axes` | `beamformed` 和 `sample, beam` |
| `shape`、`dtype`、`sample_rate_hz` | 实际保存数据的形状、类型、采样率 |
| `beams` | 与列对应的 ID、方向完整定义、固定指向说明 |
| `source_mapping` | 输入身份、源文件/字段、原始样本范围、阵元 ID 及对应顺序 |
| `time_mapping` | 输出索引 0 对应的源时间、采样间隔、延时参考、处理延迟、裁剪量及分片映射 |
| `valid_intervals` | 每条波束有效的零基半开样本区间；对应边界、缺口或失败区间及原因 |
| `units`、`amplitude_convention` | 实际单位、权重归一化、变换尺度；不把 unknown 擅自变成 Pa |
| `frequency_coverage` | 请求与实际处理频带、频带外规则、带限声明 |
| `configuration` | 本算法及公共处理的实际完整配置、模型、预处理历史和参数记录引用 |
| `weights` | 实际复数权重的文件/轴/更新范围，或获确认的可精确复现记录；两者都缺失时不得称完全可复现 |
| `quality` | 数值检查、时间对齐和重建检查、MVDR 稳定性诊断、未验证条件及接受的近似 |
| `software` | 实现版本、依赖版本和必要的数值环境信息 |

`valid_intervals` 以实际保存数组索引为准；`source_mapping` 独立保留原始索引。不同波束有不同失败范围时分别记录，不压缩时间轴来掩盖缺段。无有效样本则不得生成下游就绪结论。

### 状态与覆盖

`result.json` 至少分开记录：

- `parameter_status`：`complete`、`needs_input` 或 `invalid`。
- `implementation_status`：按能力分开记录；v0.2 入口不执行数值计算，v0.3 的 CBF/MVDR 为 implemented_limited_profile，不能概括为完整工程验收通过。
- `execution_status`：`not_run`、`blocked`、`completed`、`partial` 或 `failed`。
- `issues`：问题、影响的阶段/算法/范围、需要的处理决定。
- `coverage`：请求与实际完成的算法、样本区间、通道、方向、频带，以及源数据总范围。
- `artifacts`：实际存在且已核对的文件及角色；不能列出未生成的波形或测试结果。
- `handoff_status`：`not_requested`、`ready` 或 `blocked`；`ready` 仅表示指定结果满足接收契约，不代表已经运行检测。

参数齐全不代表算法已实现。完成指定片段不代表完成整个源文件；完成计算不代表工程质量合格。

## 6. 辅助结果及线谱检测交接

辅助产物按用户请求或任务目标自主选择，保存数值矩阵及坐标，图片只用于展示：

- 复数波束时频数据：显式轴 `[frame, frequency, beam]`、频率/时间坐标、变换参数与尺度。
- 每波束 PSD、LOFAR：声明线性功率/PSD/dB、单边/双边及参考值，不将显示强度当定量功率。
- 空间谱、频率—角度图和时间—角度图：声明时间/频率汇总方式、范围及归一化；不当作波束时域信号。
- MVDR/Capon 扫描谱、加载后的目标函数和从实际输出计算的功率须按计算定义分别命名，不能无条件互换。

默认不把数组按各自峰值归一化后交给下游。显示归一化另存配置，不覆盖原定量结果。对比图使用共同参考与色标，或明确仅比较形状。

交给线谱检测时，以已保存的时域文件及其 metadata 为主，明确算法、beam ID、采样率、时间映射、有效区间、单位、已处理频带和预处理历史。多波束逐条保留身份交接；选择交接子集仍需明确范围，不自动选最强波束。实际检测方法、检测参数确认和检测计算属于下游，不是交接的一部分。不因生成了 PSD 就擅自将时域接口改成 PSD 接口。

线谱 Skill 已新增显式选束、单束 NPY 与有效掩码/来源保留的交接接收器，见 [线谱交接说明](line-spectrum-handoff.md)。交接实现 v0.1.1 只传递数据、元数据、完整上游配置及已知限制，生成交接说明，不再生成检测参数草稿。本次合成及 VLA 数据交接已验证，详见 [验收记录](acceptance-v043.md)；检测开发不属于本模块范围。不能把数据链路通过称为检测联调成功。

## 技术依据

下列资料用于核对接口类别与重建条件，不授权采用其示例值、默认值或特定依赖：

- [ARLpy beamforming](https://arlpy.readthedocs.io/en/latest/bf.html)：区分时域输出、复数输出与功率输出，宽带处理按频率处理。
- [MathWorks Subband MVDR](https://www.mathworks.com/help/phased/ref/phased.subbandmvdrbeamformer-system-object.html)：区分待处理与训练数据、方向、波束信号及各子带权重。
- [SciPy ShortTimeFFT](https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.ShortTimeFFT.html)：复数 STFT、可逆条件、合成窗以及边界影响。
